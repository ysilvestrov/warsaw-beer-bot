# Node 24 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the production host from end-of-life Node 20 to Node 24 LTS, rebuild the one native
module that depends on the ABI, and make the repository declare and test the runtime it actually runs.

**Architecture:** Three tasks in a fixed order. Task 1 proves Node 24 works using a throwaway tarball
prefix — no apt transaction, no service stopped, nothing system-wide touched. Task 2 crosses the only
dangerous interval (new interpreter, old `better_sqlite3.node`) with both services deliberately down.
Task 3 lands the repository changes **after** the host is already on 24, so CI never claims to test a
runtime production is not running.

**Tech Stack:** Ubuntu + NodeSource apt packages, systemd, `better-sqlite3` (compiled from source),
Vitest, GitHub Actions, Dependabot.

**Spec:** `docs/superpowers/specs/2026-08/2026-08-20-458-node-24-upgrade-design.md`

## Global Constraints

- **Target runtime: Node 24 (`24.19.0-1nodesource1`).** Not 22 — see the spec's "Why 24 and not 22".
- **The host moves first, the repository second.** Task 3's pull request must not merge until Task 2
  has succeeded and the bot is healthy on 24.
- **`deploy/deploy.sh` is not modified by this work.** It is invoked. Its existing order —
  `npm ci` → `npm run build` → `npm prune --omit=dev` → `systemctl restart` → record the #435
  baseline — is what makes the ABI window safe.
- **The rollback anchor (`nodejs_20.20.2-1nodesource1_amd64.deb`) must be downloaded before the apt
  sources file is rewritten.** After the rewrite, 20.x leaves the index and there is no local cache.
- **The rehearsal never touches `/usr/bin/node`, `/var/lib/warsaw-beer-bot/bot.db`, or the real
  Telegram token.** A second live instance would fight the running bot for `getUpdates`.
- **Both services (`warsaw-beer-bot`, `48-hours-trip`) are stopped across the ABI window.**
- **`~/.local/state/wbb-autodeploy/PAUSED` is held for the whole of Task 2**, so #435's timer cannot
  deploy into a half-changed host.
- **Root operations belong to the operator, not the agent.** `sudo` on this host prompts for a
  password for everything except the pinned NOPASSWD set (which covers `deploy.sh`'s own commands and
  `sudo -u warsaw-beer-bot bash -lc …`, but **not** `apt`, and **not** `systemctl … 48-hours-trip`).
  Per `CLAUDE.md`, operator commands are delivered as a script under `./tmp/`, never printed for
  copying.
- **`./tmp/` is ephemeral and uncommitted.** Everything the plan writes there is deleted at the end;
  the rollback anchor therefore lives in `~/nodejs-rollback/`, not in `./tmp/`.

- [ ] **Step 3: Write the rehearsal script**

Create `./tmp/458-rehearse.sh`:

```bash
#!/usr/bin/env bash
# #458 — prove Node 24 runs this project, changing NOTHING system-wide.
# No apt, no systemctl, /usr/bin/node untouched, real DB and real token untouched.
set -euo pipefail

TMP=/home/ysi/warsaw-beer-bot/tmp
PREFIX=$TMP/node24
WORK=$TMP/458-rehearsal
LOG=$TMP/458-rehearsal.log

rm -rf "$PREFIX" "$WORK"
mkdir -p "$PREFIX" "$WORK"
tar -xJf "$TMP/node-v24.19.0-linux-x64.tar.xz" -C "$PREFIX" --strip-components=1
export PATH="$PREFIX/bin:$PATH"
hash -r

{
  echo "=== runtime under test ==="
  node -v
  npm -v
  test "$(node -v)" = "v24.19.0" || { echo "WRONG NODE ON PATH"; exit 1; }

  echo
  echo "=== root: install, build, test ==="
  git -C /home/ysi/warsaw-beer-bot archive HEAD | tar -x -C "$WORK"
  cd "$WORK"
  npm ci
  npm run build
  npm test

  echo
  echo "=== better-sqlite3 load probe (the segfault in #458 happened at require()) ==="
  node -e '
    const Database = require("better-sqlite3");
    const db = new Database(":memory:");
    db.exec("create table t(x)");
    db.prepare("insert into t values (?)").run(42);
    console.log("better-sqlite3 ok, round-trip:", db.prepare("select x from t").get().x);
  '

  echo
  echo "=== extension: install and test ==="
  cd "$WORK/extension" && npm ci && npm test
  cd "$WORK"

  echo
  echo "=== consistent copy of the production database ==="
  # VACUUM INTO, never cp: the live WAL is ~26 MB and a plain copy is torn.
  sudo -u warsaw-beer-bot bash -lc \
    "sqlite3 /var/lib/warsaw-beer-bot/bot.db \"VACUUM INTO '/tmp/458-bot-copy.db'\""
  sudo -u warsaw-beer-bot bash -lc "chmod a+r /tmp/458-bot-copy.db"
  cp /tmp/458-bot-copy.db "$WORK/rehearsal.db"
  ls -l "$WORK/rehearsal.db"

  echo
  echo "=== our own code against that copy: migrations + real queries ==="
  node -e '
    const { openDb } = require("./dist/storage/db.js");
    const { migrate } = require("./dist/storage/schema.js");
    const db = openDb("./rehearsal.db");
    migrate(db);
    for (const q of [
      "select count(*) as n from beers",
      "select count(*) as n from beers where untappd_id is not null",
      "select count(*) as n from enrich_failures",
      "select count(*) as n from match_links",
    ]) console.log(q, "->", db.prepare(q).get().n);
    console.log("schema_version:", db.prepare("SELECT MAX(version) AS v FROM schema_version").get().v);
  '
  # Corrected during Task 1 execution: this project tracks its migration level in a
  # `schema_version` table (MAX(version)), not the SQLite `user_version` pragma — the
  # pragma is never touched by src/storage/schema.ts and reads 0 on every DB this repo
  # has ever produced. The original probe above printed "user_version: 0" and the
  # rehearsal log carried that meaningless value forward uncaught (see
  # ./tmp/458-rehearsal.log). The real post-migration value is 25.

  echo
  echo "=== boot dist/index.js with a deliberately invalid token, then kill it ==="
  # Proves module load + DB open + migrations under Node 24. The token is junk on
  # purpose: a second instance with the real token would fight the live bot for
  # getUpdates. Exit status is not the assertion — surviving startup is.
  set +e
  DATABASE_PATH="$WORK/rehearsal.db" \
  TELEGRAM_BOT_TOKEN="000000:invalid-rehearsal-token" \
    timeout 25s node dist/index.js 2>&1 | head -40
  echo "(boot probe finished, exit=${PIPESTATUS[0]})"
  set -e

  echo
  echo "=== REHEARSAL COMPLETE ==="
  date -u
} 2>&1 | tee "$LOG"
```

- [ ] **Step 1: Write the rollback script first**

Write the way back before the way forward. Create `./tmp/458-rollback.sh`:

#!/usr/bin/env bash
# #458 — return the host to Node 20.20.2. Run only if the cutover failed.
set -euo pipefail
cd /home/ysi/warsaw-beer-bot

sudo systemctl stop warsaw-beer-bot 48-hours-trip

- [ ] **Step 2: Write the cutover script**

Create `./tmp/458-cutover.sh`:

```bash
#!/usr/bin/env bash
# #458 — Node 20 → 24 on this host. Run AFTER ./tmp/458-rehearse.sh is green.
set -euo pipefail
cd /home/ysi/warsaw-beer-bot

test -f ~/nodejs-rollback/nodejs_20.20.2-1nodesource1_amd64.deb || {
  echo "no rollback anchor — run Task 1 Step 1 first"; exit 1; }
test -z "$(git status --porcelain)" || {
  echo "working tree is dirty — deploy.sh would clear the #435 baseline"; exit 1; }

# 1. #435's brake: no security tag may deploy into a half-changed host.
touch ~/.local/state/wbb-autodeploy/PAUSED

# 2. Both services down. The sibling is stopped not because it needs a rebuild
#    (it is pure JS — measured) but so it cannot adopt the new runtime later, on
#    its own, unattended.
sudo systemctl stop warsaw-beer-bot 48-hours-trip

# 3. Keep the anchor somewhere root-owned while we are already elevated.
sudo install -m 0644 ~/nodejs-rollback/nodejs_20.20.2-1nodesource1_amd64.deb /var/backups/

# 4. The runtime swap.
sudo sed -i 's|node_20\.x|node_24.x|' /etc/apt/sources.list.d/nodesource.sources
grep -n 'node_2._x' /etc/apt/sources.list.d/nodesource.sources
sudo apt-get update
sudo apt-get install -y --only-upgrade nodejs
node -v
case "$(node -v)" in
  v24.*) echo "runtime is 24, continuing";;
  *) echo "UNEXPECTED NODE VERSION — run ./tmp/458-rollback.sh"; exit 1;;
esac

# 5. THE ABI WINDOW CLOSES HERE. deploy.sh does npm ci (rebuilds
#    better_sqlite3.node against the new ABI), build, prune, restart, and
#    records the #435 baseline.
bash deploy/deploy.sh

# 6. The sibling: pure JS, so a start is all it needs.
sudo systemctl start 48-hours-trip

# 7. Verify before releasing the brake.
sleep 5
systemctl is-active warsaw-beer-bot 48-hours-trip
journalctl -u warsaw-beer-bot -n 30 --no-pager
journalctl -u 48-hours-trip -n 15 --no-pager
echo
echo "Node: $(node -v)   better-sqlite3 rebuilt for: $(sudo -u warsaw-beer-bot bash -lc 'cd /opt/warsaw-beer-bot && node -p "process.versions.modules"')"
echo
echo "If both journals look healthy and the bot answers in Telegram, release the brake:"
echo "    rm ~/.local/state/wbb-autodeploy/PAUSED"
```

The brake is **not** released by the script. Releasing it is the operator's explicit act after
looking at the journals — a script that both verifies and clears its own safety catch is a script
that clears it on a bad day too.

- [ ] **Step 1: Write the guard test**

Create `scripts/workflow-node-version.test.ts`:

```typescript
import { readdirSync, readFileSync } from 'node:fs';
import path from 'node:path';

// #458. "CI runs what production runs" lived as a comment in ci.yml, and a comment
// cannot go red: production moved to Node 24 while five workflows still pinned 20,
// and nothing in the suite noticed. package.json's engines.node is the declaration;
// this test makes every workflow agree with it.
const root = path.join(__dirname, '..');

function declaredMajor(): number {
  const pkg = JSON.parse(readFileSync(path.join(root, 'package.json'), 'utf8'));
  const floor = /^>=(\d+)/.exec(pkg.engines.node);
  if (!floor) throw new Error(`engines.node is not a ">=N" floor: ${pkg.engines.node}`);
  return Number(floor[1]);
}

function pins(): { file: string; major: number }[] {
  const dir = path.join(root, '.github/workflows');
  const found: { file: string; major: number }[] = [];
  for (const file of readdirSync(dir).filter((f) => f.endsWith('.yml'))) {
    const text = readFileSync(path.join(dir, file), 'utf8');
    // Matches `node-version: 20` and matrix legs `- node: 20`. An expression such
    // as `node-version: ${{ matrix.node }}` carries no digit and is skipped — the
    // matrix entry it resolves to is caught by the same regex.
    for (const m of text.matchAll(/^\s*(?:-\s*)?node(?:-version)?:\s*['"]?(\d+)/gm)) {
      found.push({ file, major: Number(m[1]) });
    }
  }
  return found;
}

test('every workflow pins the Node major that package.json declares', () => {
  const expected = declaredMajor();
  const found = pins();

  // Anti-vacuity: a regex that matches nothing would make this test pass forever
  // while checking nothing at all.
  expect(found.length).toBeGreaterThanOrEqual(5);

  expect(found.filter((p) => p.major !== expected)).toEqual([]);
});
```

**Corrected during Task 3 execution**: the original text here restored with `git checkout
.github/workflows/pages.yml`. That does not work at this point in the sequence — Step 5's fix is
still unstaged and nothing has been committed yet, so `git checkout` on the path resets it to
whatever HEAD has, which is the **pre-Step-5** `node-version: 20`, not the intended `24`. Run that
way, the "restore" step still fails the guard, and the mutation proof cannot go green. Using `sed`
to flip the line back — the same tool used to break it — restores the actual intended state
regardless of what is or is not committed, which is what was used in practice.

A guard that cannot be made to fail is decoration. Record both outcomes in the pull request.
