# #612 Core Ratings Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline; AGENTS.md requires sequential execution in the main thread.

**Goal:** Persist profile personal ratings and expose them only as a fallback to check-in ratings.

**Architecture:** Add a nullable column to existing per-user had rows. Extend `markHad` and the existing shared rating reader. Keep scrape observation separate from check-in history.

**Tech Stack:** TypeScript, better-sqlite3, cheerio, Vitest; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-09/2026-09-28-612-sync-status-ratings-design.md`

## Global Constraints

- Keep the existing latest non-null check-in rating as the first choice.
- Zero is valid for personal ratings; accept only finite numeric values in 0–5.
- Missing or invalid scrape data must not erase an observed rating.
- Do not create synthetic check-ins or coverage.
- Execute in `.worktrees/612-sync-status-ratings`, branch `fix/612-sync-status-ratings`.
