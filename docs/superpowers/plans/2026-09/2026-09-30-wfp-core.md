## Уточнення до спеки, яке фіксує цей план (С §6.1 оновлено тим самим комітом)

Покриття доводить **сама сторінка**, а не стик із відомим чекіном. Сторінка стрічки — неперервний
зріз, упорядкований від нових до старих. Тому:

- **Головна сторінка** (без курсора) доводить `[t(найстарішого на сторінці), fetchedAt]`.
- **Сторінка за курсором** доводить `[t(найстарішого на сторінці), t(чекіну-курсора)]`.
- **Порожня сторінка** не доводить нічого.
- Покриття локації — об'єднання таких проміжків, незалежно від ока. Дірка між головною сторінкою
  і попереднім покриттям видна як незакритий проміжок. Відповідь маршруту
  `stitched = проміжок сторінки перетинає або торкається наявного покриття`: `false` означає, що
  око має дочитати наступну сторінку.
- `fetchedAt` від ока обрізається до `min(fetchedAt, серверний now)`: годинник ноута не
  розширює покриття в майбутнє.

Це сильніше за «стик із відомим чекіном» і не потребує, щоб чекін уже був у БД: перша сторінка
сесії одразу доводить свій проміжок.

## Задача 2 — парсер: автор, `data-gregtime`, меню

**Файли:**
- `src/sources/untappd/checkin-feed.ts`:
  - `FeedCheckin.author: string | null` — з `p.text a.user[href^="/user/"]` → `/user/<name>`;
    фолбек — перший `p.text a[href^="/user/"]`;
  - `checkin_at`: `a.time` → `attr('data-gregtime')` → інакше текст. Решта полів без змін.
  - Нова експортована функція `feedCheckinTime(raw: string): string | null` — ISO UTC з
    RFC-рядка; дата без часу (`/^\d{1,2} \w{3} \d{2}$/`, «11 Sep 26») → `null`.
    `parseCheckinFeedPage` лишає `checkin_at` як є (наявний контракт `/checkins/sync` не
    змінюється); фестивальний прийом викликає `feedCheckinTime` і **відкидає** рядки з `null`
    (С §10, «час»).
- `src/sources/untappd/venue-menu.ts` — `parseVenueMenu(html) → { updatedAt: string | null,
  items: { section, bid, name, brewery, style, abv, rating }[] }`. Селектори: `.menu-section`
  (назва секції — заголовок без суфікса «(N Items)»), `li.menu-item`, bid з `a[href^="/b/"]`.
  Позиції без bid пропускаються.

**Фікстури** (`src/sources/untappd/__fixtures__/`), **обрізані**: 3–4 рядки стрічки / 3 позиції
меню, без шапки сторінки (там акаунт власника), без `<script>`:

  тексті, `data-gregtime` нема);

Перед комітом: `grep -ciE 'csrf|authenticity|ysilvestrov|logout'` по фікстурах = 0.

**Тести:**
- DOM-фікстура: `checkin_at` = значення `data-gregtime`, а не «11 Sep 26»; `author` = точний
  username з фікстури;
- сирий фрагмент: `checkin_at` = RFC з тексту;

- меню: 3 позиції з точними bid/секцією `PINTA`/стилем/ABV; позиція без `/b/` пропущена;
  `updatedAt` з фікстури.

## Задача 3 — прийом і покриття

**Файли:**
- `src/domain/fest/coverage.ts` (чисте):
  - `pageSpan({ checkinTimes: string[] /* ISO, від нових до старих */, cursorAt: string | null,
    fetchedAt: string, now: string }) → { from, to } | null` — правило з уточнення вгорі;
  - `isCovered(intervals, from, to) → boolean` — об'єднання покриває `[from, to]` без дірок;
    дотик кінців (`a.to === b.from`) — не дірка;
  - `touches(intervals, span) → boolean` — для `stitched`.
- `src/jobs/fest-ingest.ts` — **єдиний** шлях запису для всіх очей:
  `ingestFeedPage(db, { festId, venueId, html, cursor, fetchedAt, eye, now }) →
  { inserted, seen, dropped, stitched, nextCursor }`. Кроки:
  1. `isBlockPage(html)` → кидає `BlockedPageError`;
  2. `parseCheckinFeedPage`;
  3. `feedCheckinTime` для кожного рядка; `null` → `dropped++`;
  4. для курсора: `cursorAt` — час чекіну-курсора з `venue_checkins`; нема в БД → сторінка
     покриття **не** пише (довести ліву межу нічим);
  5. `insertVenueCheckins` + `addCoverage(pageSpan)` в одній транзакції;
  6. `nextCursor` = `checkin_id` найстарішого рядка сторінки.
  `ingestMenuPage(db, { festId, html, now }) → { items, updatedAt }`: `parseVenueMenu` →
  `upsertBeerByBid` (`untappd_id_source: 'bid'`, нормалізація як у `/checkins/sync`) →
  `upsertMenuItem`.
- `src/api/routes/fest.ts` + підключення в `src/api/index.ts` за зразком `/checkins/*`
  (`authMiddleware`, `postPayloadBodyLimit` з лімітом як у `CHECKINS_SYNC_BODY_LIMIT_BYTES`):
  - `POST /fest/feed` `{ venueId, html, cursor?, fetchedAt }` → 200 з результатом `ingestFeedPage`;
    `502 blocked`; `404 no_active_fest` (поза вікном опитування); `400` на `venueId` поза
    `fest_venues`; `403 not_team_member`, якщо власник токена не учасник жодної команди фесту.
    `eye = 'laptop'`.
  - `POST /fest/menu` `{ html }` → `{ items, updatedAt }`; ті самі 403/502.

**Тести:**
- `pageSpan`: головна сторінка → `[найстаріший, fetchedAt]`; курсорна → `[найстаріший,
  cursorAt]`; порожня → `null`; `fetchedAt` у майбутньому → обрізано до `now`;
- `isCovered`: рівно суміжні проміжки → `true`; дірка в 1 с → `false`; порожній список → `false`;
- `ingestFeedPage` на фікстурі DOM: точні `inserted`/`seen`; повтор тієї ж сторінки →
  `inserted = 0`, покриття не дублюється; рядок із «11 Sep 26» без `data-gregtime` →
  `dropped = 1`; блок-сторінка (наявна фікстура блоку) → `BlockedPageError`, у БД нічого;
- курсор, якого нема в БД → чекіни записані, покриття — ні;
- маршрут: 403 для не-учасника, 404 поза вікном, 200 з точним тілом для учасника (Hono
  `app.request`, як в наявних тестах маршрутів).

## Задача 4 — Target, «на крані», рейтинг

**Файли** (усі чисті, без БД; дані подає виклик із плану 2):
- `src/domain/fest/targets.ts` — `computeTargets({ menu, triedByMember: Set<number>[],
  overrides, criteria }) → Target[]`, де `Target = { beerId, section, reasons: ('rating'|'style'|
  'manual')[], rating: number | null, style: string | null }`. Правила — С §5.
  `triedByMember` — масив множин `beers.id` на учасника; порожній масив → `[]`.
- `src/domain/fest/tap-status.ts` — `tapStatus({ bid, checkins, coverageByVenue, venueIds,
  now }) → { kind: 'on_tap', lastAt, count } | { kind: 'not_seen' } | { kind: 'unknown' }`;
  вікно `(now − 60 хв, now]`; `not_seen` лише коли `isCovered` для **кожної** локації.
- `src/domain/fest/ranking.ts` — `rankSections(targets, statusByBeer) → { section, onTap,
  unknown, total, targets }[]`, сортування — С §6.3.

**Тести:**
- targets: рейтинг 3.79 → не Target, 3.80 → Target (`['rating']`); `null`-рейтинг зі стилем
  `Stout - Imperial / Double` → `['style']`; `null` без стилю → не Target, але в окремому списку
  `unrated` (функція повертає `{ targets, unrated }`); пив один учасник із трьох → не Target;
  `add` на питу позицію → `['manual']`; `remove` на автоматичну → відсутня; шаблон
  регістронезалежний (`imperial`); жодних збігів шаблонів зі стилями `Lager - Pale` чи
  `IPA - New England / Hazy`;
- tap-status: чекін рівно `now − 60 хв` → **не** рахується (відкрите вікно), `now − 59:59` →
  `on_tap`; без чекінів, повне покриття трьох локацій → `not_seen`; дірка лише в одній локації →
  `unknown`; чекін на стадіоні з bid з меню → `on_tap` (OR по локаціях);
- ranking: точний порядок для чотирьох секцій, що перевіряють кожен ключ сортування окремо;
  секція без Target-ів відсутня.
