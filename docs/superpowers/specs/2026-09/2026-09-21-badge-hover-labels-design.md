# Видимі підказки для бейджів розширення

**Дата:** 2026-09-21
**Статус:** запропоновано

## Проблема

Кожен бейдж уже має точний `aria-label`, але його не бачить користувач мишки.
`extension/src/content/badge.ts` ставить видимий нативний підказник (`title`) лише
для `deferred` і `failed`; тому на `✅ ? ⭐ 3.6` не можна навести курсор і прочитати,
що це непевний збіг та глобальна, а не особиста оцінка.

## Рішення

Кожен намальований бейдж отримує `title`, рівний його наявному `aria-label`.
Отже браузерний hover-підказник і екранний читач повідомляють однаковий текст. Бейджі
без посилання лишаються неклікабельними; для появи підказника вони приймають наведення,
але не змінюють курсор на pointer. Клік і відкриття Untappd для вже клікабельних станів
не змінюються.

Приклад: `✅ ? ⭐ 3.6` показує й промовляє «Непевний збіг. Схоже, ти це пив. Глобальна
оцінка 3,6».

## Заявка → доказ

| Твердження, яке бачить людина | Доказ | Міцність |
|---|---|---|
| Підказник точно описує стан бейджа | `title` дорівнює `aria-label`, які обидва беруться з одного `label` у `renderState` | міцна |
| `✅ ? ⭐ 3.6` не приписує 3.6 користувачу | `foundLabel` для `unsure` уже формує «Схоже, ти це пив. Глобальна оцінка …»; `match-list.ts` не віддає `user_rating` для fuzzy | міцна |
| Підказник не змінює дію бейджа | `href` і `wireBadgeClicks` лишаються єдиною умовою навігації | міцна |

## Межі

- Не змінювати матчінг, рейтинг, `aria-label` або текст станів.
- Не створювати власний tooltip-компонент: нативний `title` уже використовується для
  помилок і не додає CSS, таймерів чи конфліктів із сайтами магазинів.
- Оновити `spec.md`, обидві інструкції встановлення та `extension/CHANGELOG.md`, бо
  hover-підказка є видимою поведінкою розширення.

## Перевірка

- Додати до `extension/src/content/badge.test.ts` таблицю/перевірку, що кожен клас
  бейджа має `title === aria-label`; окремо зафіксувати непевний випитий стан.
- Запустити тести розширення, повний `npm test`, `npm run typecheck`, збірку розширення
  та рендеринг документації.
