# Фестивальні Target за міцністю

## Проблема

Target фесту визначають два автоматичні правила: рейтинг (`rating_global ≥ target_min_rating`) і
підрядок стилю (`target_style_patterns`). Фестивальні прем'єри рейтингу ще не мають, тож для них
працює лише стиль — а міцне пиво буває в стилі, якого жоден шаблон не вгадає.

## Виміри (прод-БД, меню WFP22, 2026-10-12)

580 позицій меню; 202 пив хоч хтось із команди; 378 непитих, зі 172 без рейтингу. Після
оновлення шаблонів (операційно, того ж дня) Target — 132. Серед решти 246 міцність ≥ 8% мають 9:

| Стиль | Пиво | ABV |
|---|---|---|
| IPA - Belgian | Stargazer WFP Speciality 1–3 | 9.0 |
| IPA - Belgian | Duvel Tripel Hop Krush | 8.4 |
| IPA - Triple New England / Hazy | Potrójny Wujek z Ameryki 21° | 8.5 |
| Sour - Smoothie / Pastry | Gelato Xtreme Bloody 30° | 8.0 |
| Farmhouse Ale - Saison | Saison Farmhouse Ale | 8.2 |
| Belgian Strong Golden Ale | Aframoon (2026) | 9.5 |
| Strong Ale - Other | Emperor | 12.0 |

Сім із дев'яти не мають рейтингу. Міцність у `beers.abv`: серед 378 непитих `NULL` — 1, `0` — 13
(у нашому каталозі `0` означає «невідомо»: Old / Stock Ale «Starosta» має `0.0`).

### Відхилений варіант: шукати шаблони ще й у назві

Перевірено на тому ж меню: пошук чинних шаблонів у назві пива додав би 2 позиції, обидві хибні —
«Gelato: **Wild** Strawberry…» (смузі 5.5%) і «Summertime **Tomato** & Basil» (гозе 3.5%, який і
так відсіяно свідомо). Жодного «Freeze Distilled у назві при базовому стилі» в меню немає: всі
такі позиції вже мають стиль `Freeze-Distilled Beer` або `Porter - Smoked`. Користі нуль, шум є.

## Рішення

Третє автоматичне правило: пиво, непите кожним учасником, стає Target, якщо
`abv ≥ target_min_abv`.

- `fests.target_min_abv REAL`, nullable. `NULL` — правила немає (поведінка як досі).
- `TargetCriteria.minAbv: number | null`, `TargetMenuItem.abv: number | null`.
- Нова причина `'abv'`; порядок причин: `rating`, `style`, `abv`, `manual`.
- Пиво з невідомою міцністю — `abv = NULL` або `abv = 0` — за цим правилом не проходить за
  жодного порога, зокрема й нульового чи від'ємного (AI-рев'ю PR #861: порівняння `0 ≥ 0`
  пропускало «невідомо»). Сам поріг не перевіряється: його виставляє оператор, як і шаблони.
- Список `unrated` означення не міняє (непите, без рейтингу, без жодної причини), тож міцне пиво
  без рейтингу переходить із нього в Target.
- `/fest targets` показує причину міткою `💪` (`fest.reason_abv`), без числа.
- Ручні `add`/`remove` діють як досі: `remove` знімає й Target за міцністю.

### Міграція й значення

v48: `ALTER TABLE fests ADD COLUMN target_min_abv REAL;` — чистий expand. Попередній реліз читає
`fests` через `SELECT *` і зайве поле ігнорує; причини Target ніде не зберігаються. Відкат лише
коду безпечний.

Значення для `wfp22` (8) виставляється операційно після деплою, тим самим способом, що й шаблони
12.10: `UPDATE fests SET target_min_abv = 8 WHERE slug = 'wfp22'`. У міграцію `UPDATE` не
кладеться: це налаштування, а не схема, і contract-лінтер слушно позначив би його.

## Заявка → доказ

Зміна не записує нових фактів: `target_min_abv` — налаштування оператора, причини Target
обчислюються на кожен запит і не зберігаються. Єдине, на що правило спирається, — `beers.abv`;
його слабкість (`0` = невідомо, 14 із 378) виміряна вище й веде лише до пропуску, не до хибного
Target.
